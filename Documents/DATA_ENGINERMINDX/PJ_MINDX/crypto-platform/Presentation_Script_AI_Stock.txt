# SLIDE 6: DATA PIPELINE (Quá trình ETL) 🔥 (SLIDE ĂN ĐIỂM DATA ENGINEER)

[Nội dung trên Slide]
(CẦN HÌNH ẢNH: Ảnh chụp Python script đoạn Extract JSON thô và đoạn Transform dùng Pandas)
Chi tiết quá trình ETL (Extract - Transform - Load):
- EXTRACT (Trích xuất): Kéo dữ liệu JSON từ API (Có cơ chế tự động Sleep 60s để chống Rate Limit).
- TRANSFORM (Biến đổi - Data Processing):
  + Làm sạch dữ liệu (Drop null, ép kiểu Text về Numeric để làm Chart).
  + Tính toán chỉ số phái sinh bằng Pandas (rolling window): Moving Average (MA5, MA10), Biên độ (Volatility).
  + Tạo tín hiệu xu hướng (Trend Signals): Hệ thống tự sinh nhãn "Bullish" (Mua) nếu Giá đóng cửa > MA5 > MA10_ hoặc "Bearish" (Bán) ở điều kiện ngược lại.
- LOAD (Tải dữ liệu): Chèn (Insert/Upsert) vào kho PostgreSQL.

[Gợi ý thuyết trình (Nói)]
"Phần cốt lõi Data Engineer nằm ở luồng ETL. Ở giai đoạn Extract, em có cài cắm cơ chế bắt Try/Catch để xử lý lỗi Rate Limit của API. Ở giai đoạn Transform tầng Silver, Pandas sẽ dọn sạch dữ liệu rác, sau đó ở tầng Gold, em dùng hàm rolling của Pandas để tính trung bình trượt MA5, MA10 và tự động sinh ra tín hiệu Mua/Bán (Bullish/Bearish). Cuối cùng dữ liệu được UPSERT vào Data Warehouse thông qua thư viện Psycopg2."

[Nội dung trên Slide]

Quản lý luồng tự động (Automation):

- Vai trò điều phối:

[Gợi ý thuyết trình (Nói)]

Nếu API Alfa Vantage sập, Airflow sẽ có cơ chế alert hoặc tự động chặn các luồng đằng sau lại để không làm nát Database."

# SLIDE 9: BEST PRACTICES & ENGINEERING MINDSET 🔥 (ĐỈNH CAO KIẾN TRÚC - THÊM MỚI BẮT BUỘC)

[Nội dung trên Slide]
Các kĩ thuật tính toán & bảo vệ luồng Data mạnh mẽ:
- Tính Lặp Khả Biến (Idempotency): Pipeline dùng `UPSERT (ON CONFLICT DO UPDATE)` ở PostgreSQL. Cho dù Airflow chạy lỗi và chạy lại 100 lần, Database không bao giờ bị đúp dòng (Duplicate), đảm bảo tính toàn vẹn 100%.
- Cấu trúc Linh Hoạt (Schema Evolution): Tầng Bronze lưu trọn vẹn `JSONB` thô -> Nếu tương lai API đổi cột, DB không bị sập (Crash), ta luôn khôi phục được Data cũ.
- Fault Tolerance (Khả năng chịu lỗi): Code Python Extract có bắt Catch Exception và `time.sleep()` 60 giây khi bị khóa Rate Limit thay vì văng Exception làm đứt gãy luồng Pipeline.

[Gợi ý thuyết trình (Nói)]
"Thứ làm cho Data Pipeline của dự án này đạt chuẩn Production là tư duy làm hệ thống bền bỉ. Em áp dụng Nguyên tắc Lặp Khả Biến (Idempotent), tức là em viết SQL dùng lệnh UPSERT. Do đó dù Airflow có bị hỏng chạy lại 10 lần một ngày, DB em vẫn update đè lên giá trị mới nhất chứ không bị phình to rác data. Thêm nữa, tầng Bronze lưu bằng JSONB giúp database sống sót mượt mà ngay cả khi đối tác API họ thay đổi cấu trúc dữ liệu."

Kiến trúc RAG (Retrieval-Augmented Generation) chống ảo giác:
- Vấn đề: AI thông thường trả lời bừa, kiến thức cũ.
- Giải pháp:
  1. Retrieve: Backend Query kéo toàn bộ Data hiện tại từ `gold.v_market_snapshot` (Giá, MA5, Tín hiệu Bullish/Bearish) và 3 bài báo (News) mới nhất.

  3. Generate: Gửi bối cảnh đó cho GPT-4o-mini kèm câu hỏi của User.
- Kết quả: Chatbot AI trả lời CHÍNH XÁC dự trên dữ liệu Live DB, phân tích sắc sảo dưới góc nhìn F0.
